## 5. 文件归属语义修正情况（本轮最重要的设计修正）

**修正前问题**：M2 归属引擎把"位于工具数据目录"直接产出 Verified 归属（如 .codex 子树 4,241 条），且继承把该结论传播到子树全部文件——这在语义上混淆了"工具关联"与"文件生成来源"。

**修正方案（本轮落地）**：
1. **两维度分离**（数据层固化）：
   - 维度 A 工具关联 = attributions 表原有语义（tool_id/confidence/score/basis），**保留**；
   - 维度 B 来源行为 = 新列 `attributions.source_behavior`（v4 迁移，`TEXT NOT NULL DEFAULT 'unknown'`）：枚举 AI_CREATED/AI_MODIFIED/AI_DOWNLOADED/USER_CREATED/BROWSER_DOWNLOADED/SOFTWARE_CREATED/COPIED_OR_MOVED/UNKNOWN。
2. **自动分析不判定来源行为**：归属 pass 写入的每条结论 `source_behavior='unknown'`——系统自动判断只回答"与哪个工具有关、多可信"，不回答"是不是 AI 生成的"。只有用户确认（SOURCE_CONFIRMED，M3 功能）才能改变。
3. **继承语义澄清**：Verified 目录继承 = "位于该工具数据目录内"的关联继承（工具的配置/缓存/会话文件确实属于该工具管理），**不是**"全部 AI 生成"。UI 与 basis 措辞已按此校准。
4. **UI 两维度说明框**：识别中心顶部固定展示"①工具关联（本页）②文件来源行为——来源行为全部标记为「未知」，只有你手动确认才能改变"。
5. 真实库验证：v4 迁移后 4,245 条归属全部 source_behavior='unknown'（node:sqlite 实测）。

**明确保留**：.codex 内文件归属 codex（Verified 工具关联）是正确且有用的——它回答"这 32.6MB 是 Codex 的数据"；它不回答"这些文件是不是 AI 生成的"。

**审查轮设计修正（2026-11-05）**：原「自动分析永不填写 source_behavior」调整为**三层分模型**（本轮仅修订设计，未实现自动来源推断）：

1. **原始事件与证据层**：记录系统实际观察到的操作（扫描差异、文件系统事件、官方工具事件、用户确认）——只记事实，不下结论；
2. **自动来源判断层**：仅在可靠证据存在时产生**来源候选**——候选值（AI_CREATED/AI_MODIFIED/AI_DOWNLOADED/…）、可信度、证据说明，独立于用户确认存储；
   - 约束：只有工具目录/路径/文件名/时间关联时，**不得**判定 AI_CREATED；
   - 有可靠的官方工具事件（如工具官方操作记录）时，可研究自动建立 AI_CREATED/AI_MODIFIED 候选；
   - AI 下载与 AI 生成严格区分；普通软件/浏览器/用户操作各有独立来源判断通道；
   - 不为提高识别率降低证据要求；
3. **用户确认层**：确认、纠正或保留未知；与自动候选**分开存储**（用户确认最高可信，自动候选永不覆盖用户确认）。

数据库现状不变：4,245 条归属的 source_behavior 仍全部为 'unknown'（v4 DEFAULT）；候选表与确认表为 M3-A 设计目标，本轮未实现。

## 14. FMap 长期产品方向（本轮正式确定）

FMap 从"AI 文件识别器"升级为**文件来源与生命周期追踪系统**：解释电脑中文件从哪里来、经历了什么变化、为什么在当前位置。核心价值排序：**真实性 > 隐私 > 覆盖面**——宁可显示未知，不可编造来源。

**两维度模型（永久原则）**：
- 维度 A 工具关联：文件/目录与工具的关联强度（M2 已实现）
- 维度 B 来源行为：AI_CREATED / AI_MODIFIED / AI_DOWNLOADED / USER_CREATED / BROWSER_DOWNLOADED / SOFTWARE_CREATED / COPIED_OR_MOVED / UNKNOWN——采用**三层分模型**（审查轮修正，见 §5）：原始事件与证据 → 自动来源判断（仅在可靠证据存在时产生候选+可信度+证据说明，与用户确认分开存储）→ 用户确认（最高可信，可纠正/保留未知）。当前约束：仅目录/路径/文件名/时间关联**不得判定 AI_CREATED**；AI 下载与 AI 生成严格区分；普通软件/浏览器/用户操作独立判断；Unknown 永久保留；不为识别率降低证据要求。**M2 现状：全部 unknown（诚实基线），自动候选能力属 M3-C 规划。**

**五类追踪对象**：AI 生成 / AI 修改（与 AI 创建严格区分）/ AI 下载引入（与 AI 生成严格区分）/ 普通文件来源（浏览器/软件/安装程序/解压/外部设备）/ 来源未知（正式状态，保留首次发现时间与证据，允许用户修正）。

**证据能力边界表（审查终版新增——每种证据能证明什么、不能证明什么）**：

| 证据类型 | 可以证明 | 不能证明 |
|---|---|---|
| 工具数据目录（.claude/.codex 等） | 文件与该工具的存储位置关联 | 文件由 AI 生成 |
| 项目信号文件（CLAUDE.md/AGENTS.md 等） | 项目可能使用某个工具 | 项目内所有文件均由该工具生成 |
| 文件创建时间 | 文件大致出现时间 | 谁创建了文件 |
| 文件修改时间 | 文件发生过修改 | 修改者是谁 |
| 时间共现（工具运行期间出现） | 时间上相关 | 创建者/修改者、来源行为 |
| 进程-文件操作关联（需授权） | 某进程执行了写入操作 | 进程背后是 AI 还是用户、意图 |
| 官方工具操作事件 | 工具明确记录的文件操作 | 超出事件记录范围的行为 |
| 文件系统事件（USN/RDCW） | 文件系统发生了某项变化 | 变化的完整业务原因 |
| 用户主动确认 | 用户明确提供的来源 | 用户未确认的其他历史事件 |

原则：**任何单一证据都不足以判定 AI_CREATED/AI_MODIFIED**——只有官方工具事件、进程级可靠归因或用户确认这类强证据才能触发来源行为候选（见 §5 三层分模型）。

## 15. 文件生命周期模型建议（M3 研究目标）

**事件模型**（草案，M3-A 落地时评审）：FILE_DISCOVERED（首次发现）/ FILE_CREATED / FILE_MODIFIED / FILE_DOWNLOADED / FILE_IMPORTED / FILE_COPIED / FILE_MOVED / FILE_RENAMED / FILE_DELETED（**必须有事件证据**；扫描缺失≠删除）/ SOURCE_CONFIRMED / SOURCE_CORRECTED（用户操作）。

**文件身份**（关键技术问题，禁止只用路径）：
- 方案 1：卷标识 + NTFS File ID（`GetFileInformationByHandleEx` 的 FileIndex）——普通权限可用、移动/重命名后身份保持；跨卷移动即新身份；不读内容、零隐私成本 → **推荐主键基础**
- 方案 2：受控 Hash（仅对用户显式授权的文件、可配置大小上限）——用于内容级关联（重复/覆盖检测），默认关闭
- 方案 3：路径+mtime 弱身份——降级方案（FAT32/exFAT 等无 File ID 的文件系统）

**方案 1 深度评估（审查轮补充）**：
- **实际 API**：BY_HANDLE_FILE_INFORMATION.nFileIndexLow/High（64 位）；GetFileInformationByHandleEx(FILE_ID_INFO) 返回 128 位 FileId（主要面向 ReFS）；**批量路径**：目录枚举类 FILE_ID_EXTD_DIRECTORY_INFO 可在枚举时同步返回每条目的 FileId——无需逐文件开句柄 [Microsoft Learn；适用 Windows 版本范围**待验证**]
- **权限**：FILE_READ_ATTRIBUTES（不读正文），普通用户可用 ✅
- **硬链接**：同一 File ID = 天然识别硬链接（去重计量直接受益）；"链接组新增名称"与"移动"的区分【链接组枚举 API（FileLinksInformation）**待验证**】
- **跨卷移动**：File ID 属于卷 → 跨卷移动产生新身份，需靠事件流关联（M3-E 路线）
- **删除后 ID 重用**：NTFS MFT 记录号在文件删除后**可能被重用**（Microsoft 文档明确警告 File ID 不保证长期唯一）→ 身份校验必须组合 (size, mtime)，"消失+同 ID 重现"标记为待确认事件【重用窗口实测**待验证**】
- **卷格式化/重挂载**：重格式化后 ID 语义重置；仅盘符变化的重挂载不影响 → 身份键应使用 (VolumeGuid, FileId) 而非盘符【GetVolumeNameForVolumeMountPointW **待验证**】
- **文件系统兼容**：NTFS = MFT 记录号（64 位）+ 删除后可能重用；ReFS = 128 位 FileId、重用行为**待验证**；FAT32 = FileIndex 由首簇派生、删除后重用常见；exFAT = 行为**待验证** → 各文件系统均**不保证长期唯一**，走降级链
- **50 万历史路径迁移成本：估算值（非实测）**——批量枚举路线 ≈ 现有扫描同量级（参考 E 盘 14.7s/27.9 万文件实测）≈ 1 分钟级；逐文件回退（每文件 1 handle）≈ 数分钟到数十分钟【估算，未实测】；本轮未批量读取真实文件身份（遵守任务边界）
- **采集性能/权限**：批量枚举与现有扫描同句柄（零额外句柄）；逐文件回退 = 每文件 1 个 handle（FILE_READ_ATTRIBUTES）→ 50 万文件约数分钟【待实测】
- **结论**：File ID 是 NTFS 场景最佳主身份，但**不是**所有文件系统的通用唯一身份——身份键 = (VolumeGuid, FileId) + 降级链，且必须接受 MFT 重用风险并设计校验。
- 跨目录移动：File ID 相同 → FILE_MOVED 事件（旧路径→新路径）；复制 → 新 File ID + 关联源；覆盖 → 同 ID + size/mtime 变化 → FILE_MODIFIED；删除后重建 → 新 File ID（正确区分"同名不同文件"）
- 降级链：File ID → (路径, size, mtime) 启发式 → 仅 FILE_DISCOVERED

## 16. 全面文件来源追踪技术调研

| 技术路线 | 能采集 | 不能采集 | 权限 | 常驻 | 隐私 | 默认开启 | 授权方式 |
|---|---|---|---|---|---|---|---|
| 目录扫描（已实现） | 路径元数据、存在性 | 变化历史、来源 | 普通用户 | 否 | 低（仅元数据） | ✅ | 无需 |
| USN Journal（NTFS） | 创建/删除/重命名/数据扩展事件流（卷内单调有序） | 内容、进程；ReFS 支持性**待验证** | **卷句柄需 GENERIC_READ → 需管理员**（FSCTL_ENUM/READ_USN_JOURNAL，M1 技术报告已核）；单文件 FSCTL_READ_FILE_USN_DATA 免管理员但非事件流 | 可选后台 | 中（全卷事件流） | ❌ 逐项授权 | 高级授权（或系统服务，须评估） |
| ReadDirectoryChangesW（M0-M1 已验证可行） | 监视目录内变化事件（递归单句柄；NTFS/FAT32/exFAT/CDFS 本地卷；网络重定向卷不可靠【待验证】） | 进程、远端原因、完整业务原因；**缓冲溢出丢事件**（ERROR_NOTIFY_ENUM_DIR → 恢复方式=重新枚举目录树对账）；**同一变更可能产生重复通知**（微软文档明示→需去重键）；无顺序保证；事件合并 | 普通用户 | 监视期间是 | 低-中（仅监视目录） | ❌ | 按目录授权 |
| ETW 进程-文件关联 | 进程级操作归因 | 意图 | **需管理员** | 是 | 高 | ❌ 永不默认 | 暂缓（M5-E 评估） |
| 浏览器下载记录 | 下载历史（Chrome/Edge SQLite） | 下载内容 | 普通用户（复制库文件读取，原库只读） | 否 | 中-高 | ❌ 逐项授权 | 明确告知 |
| AI 工具操作记录 | 工具官方事件（如 Claude Code hooks） | 未记录行为 | 普通用户 | 否 | 低-中 | ❌ | 逐工具授权 |
| 包管理器记录（pip/npm 日志） | 依赖安装位置 | 谁发起 | 普通用户 | 否 | 低 | ❌ | 逐项 |
| 文件差异分析 | 修改前后对比 | 历史（无快照则不可得） | 普通用户 | 需快照策略 | 高（读正文） | ❌ | 显式授权+大小上限 |
| 用户主动标记 | 确认来源（最高可信） | 未知历史 | 普通用户 | 否 | 零 | ✅（功能本身） | 用户自发 |
| macOS/Linux 事件 | FSEvents/inotify 事件流 | 同 Windows 限制 | 普通用户 | 可选 | 中 | ❌ | 同 Windows 原则 |
| 目录扫描差分（M3-B） | 两次快照间的增/改/消失 | 变化原因、删除的确凿性 | 普通用户 | 否（扫描时） | 低 | ✅（核心功能） | 无需额外授权 |

**事件可靠性要点（审查轮补充）**：
- **USN 丢失/轮转/截断**：USN Journal 是环形缓冲——写满后旧记录被覆盖（wrap），chkdsk/卷维护可截断；消费方必须检测 NextUsn 回跳并**全量重建**（不丢已入库数据，标记该段事件缺失）【恢复流程细节**待验证**】
- **事件顺序与去重**：USN 卷内单调（可作排序依据）；RDCW **无顺序保证**且可能合并——去重键 = (路径, 事件, mtime)，配合 debouncer
- **文件系统支持**：USN 仅 NTFS（ReFS **待验证**）；RDCW 支持 NTFS/FAT/CDFS 等；exFAT 无 USN → 走扫描差分
- **后台成本**：RDCW = 每监视目录 1 句柄 + 缓冲；USN = 系统本就维护（成本在消费端）；两者隐私成本 = 被监视范围的完整文件活动流 → **默认关闭，逐目录/逐功能授权**

结论（审查轮修正）：**默认只开目录扫描；目录监视（RDCW）为 M3-B 主线（普通权限可行）；USN Journal 因需管理员权限移入 M3-E 评估（或系统服务方案，须单独评审）；进程关联/浏览器读取/差异分析列入高级授权池，绝不默认开启；永不安装驱动或要求关闭安全功能。**

## 17. M3 分阶段路线图

### M3-A：文件资产基础模型（推荐最先，普通权限、低隐私增量——见隐私与性能说明）
- 目标：文件实体（卷+File ID 主身份）+ 事件表 + 证据表 + 用户确认表；M2 归属兼容（attributions 成为"工具关联证据"的一种）
- 数据库（**六职责模型，审查终版设计**——本轮仅设计，不执行 v5 迁移）：
    - `file_entities` 文件身份（卷序列号/卷 GUID + FileId + 校验位；含降级链字段）——身份解析唯一入口
    - `file_events` 原始事件（append-only，含 evidence 引用）——**不可被自动判断覆盖**
    - `source_evidence` 原始证据（独立表：证据类型/来源/采集时间/适用范围）——与事件分开存；自动候选只引用证据 id
    - `source_candidates` 自动来源候选（**可整体重建**：规则/证据更新后 DELETE+重算，不影响事件与确认）
    - `source_confirmations` 用户确认/修正（append-only 保留修正历史；最高可信，覆盖候选展示）
    - `tool_associations` = **M2 attributions 表原样保留**（工具关联维度独立），不转换成 AI_CREATED/AI_MODIFIED，不并入来源模型
    - UNKNOWN 永久保留为合法结论；每条记录带 [自动候选/用户确认] 区分标记
  - attributions 增 entity 关联（迁移 v5 的一部分；历史数据不动）
- IPC/UI：文件详情页显示"事件时间线+证据"；用户确认对话框
- 验收：合成树事件对账；既有 508K 路径无损迁移；迁移安全测试（沿用 v4 框架）
- **隐私与性能（审查轮修正——不再笼统称"零隐私增量"）**：
  - 不读取文件正文 ✅ · 不上传任何数据 ✅ · 不做内容 Hash ✅
  - **新增元数据采集**：文件身份（卷+File ID）——批量目录枚举同句柄取得（零额外句柄）；逐文件回退 = 每文件 1 个 handle（FILE_READ_ATTRIBUTES）
  - **磁盘/性能成本**：存量 50 万路径一次性重枚举约 1 分钟级（E 盘 14.7s 实测同量级推算）；此后增量扫描零额外成本；批事务 5000/批不变
  - **范围/速率/并发**：扫描范围沿用用户勾选；单卷顺序枚举；worker 并发沿用 M1 设置；监视类功能不在 M3-A
  - **用户查看与撤销（审查终版修正）**：文件身份采集**默认关闭**——用户主动授权后才开始采集；可随时暂停或撤销；撤销后停止新增身份采集；**是否删除已有身份数据由用户明确选择**；不影响现有普通路径扫描；不读取文件正文、不计算 Hash、不上传数据。（"可见、可撤销"不构成默认开启的充分理由）
- 不做：任何监控

### M3-B：基础事件追踪（扫描差分 + 可选目录监视）
- 目标：两次扫描差分 → FILE_DISCOVERED/MODIFIED/(MISSING-待证据)；可选的 ReadDirectoryChangesW 实时监视（逐目录授权）
- 数据库：events 表启用；监视会话表
- 验收：合成树增删改 → 事件精确对账；取消/崩溃一致
- 不做：USN、进程、跨卷移动推断（M3-E）

### M3-C：AI 工具行为关联（语义修正：关联 ≠ 来源行为）
- **目标修正（审查终版）**：产出**工具关联候选与时间关联记录**——时间共现只能证明时间关联，**不能证明文件由 AI 创建或修改**，因此 M3-C 不得直接产出 AI_CREATED/AI_MODIFIED 结论。
- **证据强度分级（谁能触发什么）**：
  - 工具运行期间发现文件（时间共现）→ 仅"时间关联"记 [possible]，不升级为来源行为
  - 文件位于工具数据目录（.codex/.claude 等）→ 工具关联 verified（M2 已实现；语义 = 工具管理的数据，非生成来源）
  - 项目与 AI 工具关联（信号文件/项目配置命中）→ 项目级工具关联 likely
  - 进程实际执行文件写入（进程-文件关联，需高级授权）→ 仅当进程可确证归属某 AI 工具时，产生 AI_CREATED/AI_MODIFIED **候选**（自动层）
  - 官方工具事件明确记录文件操作 → 产生 AI_CREATED/AI_MODIFIED 候选（最强自动证据）
  - 用户主动确认 → 用户确认级（最高，独立存储，可覆盖候选）
- 数据库：时间关联/候选写入 `source_candidates`（自动层，规则更新可整体重建）；用户确认写 `source_confirmations`（独立表）；**不直接写入 source_behavior**
- AI 下载依赖独立分类（AI_DOWNLOADED 候选需下载来源证据：包管理器记录/工具下载日志；仅 node_modules 目录命中不足以判定）
- 验收：真实项目工作前后扫描对比 + 语义红线复检（**时间窗结论不得标注为 AI_CREATED/AI_MODIFIED**）

### M3-D：普通文件来源追踪
- 目标：浏览器下载记录集成（可选授权）、用户标记 UI、安装程序/解压目录规则扩展
- 验收：真实下载文件被正确关联浏览器证据（用户授权后）

### M3-E：高级持续追踪（最后，逐项授权）
- 目标：USN Journal 持续追踪（NTFS）、后台监视会话、数据保留策略、跨平台评估
- 前置：M3-A/B 稳定；用户明确授权；性能预算实测

各阶段共同验收框架：§10 测试表结构 + 隐私红线检查单 + 历史数据对账。
