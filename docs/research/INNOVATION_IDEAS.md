# 创新功能清单（INNOVATION_IDEAS）

> 版本：v0.9（夜间研究稿） · 日期：2026-11-03
> 状态标记：✅ 技术已验证可行 ｜ ⚠️ 依赖外部条件 ｜ ❓ 部分环节待验证
> 评分维度：创新性 / 实现难度（1=极易，5=很难）/ 用户价值（1-5）/ 开发优先级（P0 > P1 > P2）

---

## 0. 设计前提

现有竞品（WinDirStat、WizTree、SpaceSniffer、duvis、squirreldisk 等）解决的是"**磁盘上有什么、有多大**"。
TraceNest 要解决的是"**这些文件是谁（哪个 AI 工具 / 哪个项目）产生的、能放心怎么处置**"。

因此所有创新功能都围绕一条主线：**归属（Attribution）+ 时间（History）+ 处置辅助（Safe Disposal）**。
我们不发明任何无法在"只读 + 无管理员权限 + 完全本地"约束下实现的功能。

---

## 1. 功能清单（14 项）

### F1. AI 信号文件指纹检测（Signal-File Fingerprinting）✅

**一句话**：通过检测目录中的"AI 痕迹文件"（`CLAUDE.md`、`AGENTS.md`、`.cursorrules`、`GEMINI.md`、`.codex/config.toml` 等）判定"这个目录被哪个 AI 工具工作过"。

- **原理**：各 AI 编码工具都会在项目根目录/配置目录留下约定俗成的标记文件。规则形如 `{"tool": "claude-code", "signal": "CLAUDE.md", "scope": "project-root", "confidence": "verified"}`。
- **创新性 5**：现有磁盘工具按大小/扩展名分类；没有任何工具按"AI 痕迹"归类。这是 TraceNest 最核心的差异化。
- **难度 2**：规则匹配 + 目录级权重评分，纯文件系统元数据扫描。
- **用户价值 5**：直接回答"哪些项目是 AI 参与的"。
- **优先级 P0**（V0.1 核心功能）。
- **风险**：信号文件可被用户手写（如人工维护的 AGENTS.md），需在 UI 说明"表示 AI 工具曾以此为工作目录，不代表全部文件由 AI 生成"。

### F2. AI 工具目录知识库 + 社区适配器（Declarative Rule Packs）✅

**一句话**：内置一份声明式"AI 工具目录签名库"（JSON 规则包：路径模式 → 目录类型/内容特征/官方文档链接/删除风险），社区通过 PR 贡献新工具适配器。

- **原理**：每条规则包含 `tool / paths(per-OS) / kind(install|config|cache|session|log|download) / size-profile / risk-level / source-url / status`。规则库带版本号，随应用打包，也可从本地文件导入更新（不联网拉取，符合隐私原则）。
- **创新性 4**：竞品没有"AI 工具知识库"概念；类似做法只见于卸载器类产品（如 BCUninstaller 的规则）。
- **难度 2**：本质是数据工程；本夜研究已产出第一版规则草案（见 `AI_TOOLS_DIRECTORIES.md`）。
- **用户价值 5**：AI 软件识别中心、占用排行、卸载清单全部依赖它。
- **优先级 P0**。
- **生态意义**：这是让社区参与扩展的最自然入口（第 8 问的回答）。

### F3. 归属置信度评分引擎（Attribution Confidence Engine）✅

**一句话**：每一条"某文件/目录属于某 AI 工具"的结论都显式携带三级置信度：`verified`（命中信号文件/官方目录）→ `likely`（目录模式匹配）→ `inferred`（时间/进程相关性推断）。

- **原理**：归属不是布尔值。规则引擎对每个路径输出 `{tool, score, basis[], confidence}`，UI 用颜色+图标明示，报告导出时保留依据链。
- **创新性 4**：把"诚实工程"产品化——没有竞品做归属，更没有竞品给归属标注可信度。
- **难度 3**：评分模型需要调参，但结构简单。
- **用户价值 5**：卸载决策时"verified 才高亮"能真正防误删。
- **优先级 P0**。

### F4. 项目指纹与跨磁盘资产聚合（Project Fingerprint）⚠️

**一句话**：用 `package.json`、`pyproject.toml`、`Cargo.toml`、`git remote` 等项目特征文件的内容哈希组合成"项目指纹"，把散落在 C/D/E 盘的同一项目资产（主仓库、下载缓存、导出文件）聚合到一个"项目资产"视图。

- **原理**：扫描时对**小体积**（<256KB，可配置）的纯文本特征文件计算内容哈希；指纹 = 组合键（如 name + repository url）。同一指纹的不同路径 → 同一项目。
- **创新性 5**：跨盘关联是用户痛点 4（"不知道某个文件属于哪个项目"）的直接答案，竞品全部缺失。
- **难度 3**：需要读取少量用户文件内容做哈希 → **必须**在设置中显式声明"读取哪些类型的文件"，默认白名单 = 项目清单文件，且仅本地计算。
- **用户价值 5**。
- **优先级 P1**（V0.2，因为涉及"读文件内容"这一隐私边界，需要用户确认后实施）。

### F5. 会话 ↔ 项目 ↔ 文件关联（Session Mapping）⚠️

**一句话**：解析 AI 工具的会话存储路径（如 Claude Code 的 `~/.claude/projects/<编码后的工作目录路径>/`），建立"会话 → 工作目录 → 该目录下的文件"链路，回答"上次和 AI 聊到的那批文件在哪"。

- **原理**：多数 CLI 型 AI 工具的会话存储以项目路径编码为目录名/文件名，天然携带归属信息。TraceNest 只读**元数据**（路径、大小、mtime），默认不读会话正文。
- **创新性 5**：把"AI 会话"和"文件资产"连起来是全新视角。
- **难度 3**：每个工具的编码规则不同，依赖 F2 规则库逐个适配。
- **用户价值 5**：直击"过去生成的文件在哪里"。
- **优先级 P1**。
- **隐私红线**：默认只统计会话文件的"路径+大小+时间"，正文的读取必须是显式开启的本地功能。本夜研究中被反复强调：**不读取用户的真实聊天记录**。

### F6. 共享依赖去重计量（Dedupe Metering）✅

**一句话**：识别 junction/hardlink/reparse point、pnpm store、node_modules 引用与模型缓存共享，报告"逻辑占用 vs 物理占用"两套数字，避免 WizTree 式重复计数。

- **原理**：Windows 上 `FILE_ATTRIBUTE_REPARSE_POINT` + 硬链接计数可从目录遍历获得（见 TECH_FEASIBILITY Q9）；按 reparse 目标分组即可区分"实体"与"引用"。
- **创新性 3**：部分竞品（WizTree 等）对 hardlink 有处理，但"按 AI 工具视角解释共享依赖"是新的。
- **难度 3**。
- **用户价值 4**：直接决定"AI 工具实际占了多少空间"的数字可信度。
- **优先级 P1**。

### F7. 空间快照与增量对比（Snapshot Diff / 空间回归报告）✅

**一句话**：周期性轻量重扫（mtime+size 未变即跳过），生成"本周 AI 工具新增 8.3 GB / 某项目缓存增长 2.1 GB"类趋势报告。

- **原理**：SQLite 中保存上次快照，与本次扫描做差分。配合实时监控（F11）可大幅降低重扫成本。
- **创新性 3**：竞品无历史对比（WinDirStat 每次都是全量快照）。
- **难度 3**。
- **用户价值 4**：回答"AI 是不是越用越占"。
- **优先级 P1**。

### F8. 陌生目录解释器（Directory Explainer）✅

**一句话**：在文件浏览器中选中任意目录，侧栏用知识库解释："这是什么、谁生成的、通常多大、删除风险等级、官方文档链接"。

- **原理**：F2 规则库的查询视图 + 信号文件检测结果合成。
- **创新性 4**：把"解释陌生目录"作为一等公民功能，没有竞品做。
- **难度 2**。
- **用户价值 5**：对"卸载时害怕误删"是直接止痛。
- **优先级 P1**。

### F9. 卸载安全清单（Uninstall Report）✅

**一句话**：用户想卸载某 AI 工具时，生成只读报告：该工具名下的目录/文件/大小清单，按删除风险（安全/谨慎/不要删）分级，附"建议由用户自行执行的命令"（复制到剪贴板），TraceNest 自身永不执行删除。

- **创新性 4**：是"只读"约束下的最佳替代方案——不替用户动手，但给足依据。
- **难度 2**（基于已有数据聚合）。
- **用户价值 5**。
- **优先级 P1**。
- **设计约束**：清单必须标注置信度（F3），`inferred` 级别的条目默认折叠。

### F10. MCP Server 模式：让其他 AI Agent 查询文件资产地图（Agent Collaboration）⚠️

**一句话**：TraceNest 内置一个本地 MCP server，暴露 `find_projects / tool_usage / explain_path` 等只读工具，让 Claude Code、Codex 等 Agent 直接查询"用户的 AI 文件资产地图"。

- **原理**：MCP 是 2025 年以来 AI 工具生态的标准协议，Claude Code/Codex/Cursor 均支持配置本地 MCP server。TraceNest 的 Rust 侧可轻量实现 stdio/HTTP MCP server（实现于 Tauri 应用运行时）。
- **创新性 5**：双向关系——AI 工具既是被追踪对象，又是 TraceNest 的消费者。生态卡位价值高，类似"文件资产领域的 Everything CLI"。
- **难度 3**：MCP 协议成熟、有 Rust SDK（官方 modelcontextprotocol 提供 rust-sdk，状态待验证）。
- **用户价值 4**："帮我找到上个月 Cursor 生成的项目"成为一句自然语言。
- **优先级 P2**（V0.3+）。

### F11. 实时事件流 + 历史重建（考古模式）⚠️

**一句话**：notify 监控未来文件事件；对历史，用"快照差分 + 文件时间戳 + 可选的单文件 USN 父链记录"重建近 7/30 天的变化时间线，全部标注置信度，不夸大。

- **原理边界（诚实声明）**：
  - **未来事件**：`notify` 基于 ReadDirectoryChangesW/FSEvents/inotify，无管理员权限可用 ✅；
  - **事件归属进程**：ETW 需要管理员权限 ❌ → 无法实时归因进程，只能用"进程快照 + 事件时间相关性"做 `inferred` 级推断；
  - **历史重建**：USN Journal 全量枚举需要管理员权限 ❌；单文件 USN 记录（`FSCTL_READ_FILE_USN_DATA`）普通权限可用 ✅ → 可对已知文件取 parent 引用号辅助建链，但**无法**从零重建全盘历史。
- **创新性 4**：竞品全是"静态快照"，无时间维度。
- **难度 4**：历史重建的置信度模型是难点。
- **用户价值 4**。
- **优先级 P2**（V0.3+；V0.1 只做实时事件流展示）。

### F12. AI 工具占用排行与趋势（Tool Usage Ranking）✅

**一句话**：按 AI 工具聚合磁盘占用、Top 大文件、目录类型分布（缓存/会话/模型/依赖），一张图看清"谁在吃我的硬盘"。

- **创新性 3**：数字聚合本身常见，但"按 AI 工具维度"是新的。
- **难度 1**：F2 + 扫描数据的查询视图。
- **用户价值 5**：最高频使用场景。
- **优先级 P0**（V0.1 核心）。

### F13. 隐私审计模式（Privacy Audit Mode）✅

**一句话**：设置页可查看 TraceNest 的完整行为账本：读过哪些目录、数据库里写了什么、发起过哪些网络请求（答案应为零），并提供"清除数据库"按钮与自定义 DB 位置。

- **创新性 4**：把隐私承诺做成可自查的功能，而不是口号。配合开源 = 可验证。
- **难度 2**。
- **用户价值 4**：对目标人群（开发者）有说服力。
- **优先级 P2**。

### F14. 大文件哨兵（Large-File Sentinel）✅

**一句话**：内置阈值规则（`*.gguf` / `*.safetensors` / `node_modules` / 超过 N GB 的缓存目录），在报告中心聚合"值得关注的文件"并解释其来源。

- **创新性 2**，**难度 1**，**用户价值 4**。
- **优先级 P1**（依附于 F2 规则库，成本极低）。

## 3. 明确不做的事（防伪创新）

以下想法因违反核心约束或技术不可行，**主动放弃**：

1. **进程级实时归因**：ETW 文件事件需管理员权限，违反约束 9。放弃实时归因，只做推断。
2. **全盘历史 USN 回放**：需管理员权限 + 数据量大且不可靠。放弃，改用快照差分。
3. **AI 内容识别"这个文件是不是 AI 写的"**：无法可靠验证，属于夸大宣传，且隐私成本高。放弃。
4. **自动清理/一键瘦身**：违反只读约束。只做报告与建议。
5. **云同步/多设备汇总**：违反完全本地原则。放弃。
6. **文件内容全文索引**：隐私成本高、DB 体积失控，且超出"资产地图"定位。只索引文件名（FTS5）。
